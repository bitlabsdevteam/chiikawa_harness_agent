Permissions ablation: LLM judge vs Jev

Chiikawa coding-agent harness · tool-call approval decisions · 2026-10-10 · Jev model stand-in · LLM judge stand-in · 122 synthetic gold-labelled calls
The question. The harness blocks a few obviously dangerous commands with a regex. In yolo (no-prompt) mode, everything else runs. Can a second opinion on each tool call, from the same LLM or from the Jev decision model, catch what the regex misses without interrupting safe work?

Result

With only the regex denylist, 65% (28/43) of the dangerous calls would run in yolo mode. Adding the LLM judge lowers that to 16% (7/43); adding Jev lowers it to 9% (4/43).

Overall decision accuracy is 48% for the baseline, 85% with the LLM judge, and 92% with Jev. Routine calls that get interrupted: 0% baseline, 0% LLM judge, 0% Jev.

How this was run, and its limits

  • Data: 122 synthetic tool calls labelled by one person before any run; the labels and the question wording were fixed before the run (wording fingerprint 7757ca2cfa01340d, not tuned on a dev set).
  • Same question for both models: allow, ask or deny, plus the probability the call touches secrets. The LLM judge got the same text and the same options.
  • System arms apply the regex first, then the model's advice, which can only tighten a decision (as in the harness).
  • Small sample: intervals are 95% Wilson; with this few dangerous calls (43) they are wide. One labeller, synthetic data, one run per item (a 30-item subset repeated 3×).
  • Speed was measured with up to 3 parallel requests per model, over the public internet, on one day.
  • Not tested here: context visibility, end-to-end task success, and real-session data.
  • Stopped early: {'jev': None, 'llm': None}
