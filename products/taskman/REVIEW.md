# Second design-director review — CLI ledger

Review scope: `taskman.py`, `test_taskman.py`, `README.md`, `DESIGN.md`,
`REVIEW.md`, and `QUALITY.md`. Current measured counts are in `QUALITY.md`;
the twelve findings below retain the earlier delivery's review history.

The first usable build passed 21 subprocess tests. Inspection of its help, empty output, validation and persistence code revealed the twelve deficiencies below. Every fix is implemented; the named regression tests are in `test_taskman.py`. This review applies the usability and verification bar to a terminal product, not to a webpage.

1. **Store selection depended on argument position.** `list --store PATH` failed with exit 2 although the global form worked. **Fix:** expose `--store` on every subparser with a suppressed default so later explicit paths override earlier ones without resetting them accidentally. **Evidence:** `test_store_option_after_every_command` executes all five commands with a later path and proves the earlier store remains absent.

2. **Help described syntax but not a complete next action.** Root help lacked examples; command help did not explain duplicate completion, destructive removal or dash-prefixed descriptions. **Fix:** add root and command examples, exit-code guidance, explicit no-undo wording and delimiter guidance. **Evidence:** `test_help_is_actionable_and_read_only` checks all six help screens without filesystem changes; `test_dash_prefixed_description` executes the delimiter form.

3. **Invalid IDs were misclassified as unknown tasks.** The inspected `done 0` returned a task error instead of an argument error. **Fix:** validate positive integer IDs in argparse before storage access. **Evidence:** `test_nonpositive_ids_are_usage_errors` covers zero, negative, fractional and nonnumeric values for both ID-taking commands, checks exit 2 and compares original file bytes.

4. **Filtered empty results falsely described the whole ledger as empty.** An all-completed collection suggested adding the first task; generic hints also lost the selected store. **Fix:** distinguish no open tasks, no completed tasks and an actually empty store; include the shell-quoted selected path in next-action hints. **Evidence:** `test_filtered_empty_states` exercises both transitions; `test_empty_hint_keeps_selected_store` checks a path containing spaces.

5. **Duplicate JSON keys could silently lose information.** The default decoder keeps only the last occurrence of a repeated field. **Fix:** use an object-pairs hook to reject duplicate keys at every object level. **Evidence:** `test_duplicate_json_keys_rejected` supplies ambiguous root and task fields and verifies diagnostic text and byte-for-byte preservation.

6. **Extra schema fields had no defined meaning.** A future-version-like field could be accepted even though commands did not understand its semantics. **Fix:** enforce exact root and task field sets, in addition to the existing type, uniqueness and counter checks. **Evidence:** `test_unknown_schema_fields_rejected` covers both levels; `test_invalid_schema_preserved` covers bad versions, booleans-as-integers, duplicated IDs, invalid descriptions and regressed counters.

7. **Storage diagnostics did not reliably identify the selected ledger.** A corrupt-file error omitted its path, making multiple-store recovery ambiguous. **Fix:** prefix task/storage errors with the escaped selected path; validate blank/NUL path arguments and handle failed home expansion without a traceback. **Evidence:** `test_storage_error_identifies_path`, `test_invalid_store_path` and `test_missing_parent_is_not_created` verify useful diagnostics, exit categories and unchanged filesystem state.

8. **Nonregular paths could block or replace the wrong object.** Opening a FIFO could hang; replacing a symlink could sever it rather than update an intended ledger. **Fix:** inspect with `lstat` before reads and mutations and reject symlinks, directories and nonregular files. **Evidence:** `test_fifo_store_does_not_block` runs with a subprocess timeout; `test_symlink_store_rejected`, `test_dangling_symlink_rejected` and `test_directory_store_rejected` verify preserved targets and path identity.

9. **Unicode safety stopped at ASCII-style control categories.** Unicode separators could split rows, and explicit directional formatting could disguise task content. **Fix:** reject line/paragraph separators and bidi formatting controls while retaining natural multilingual text and emoji joiners; apply identical rules on load. **Evidence:** `test_unicode_format_controls_rejected` and `test_unsafe_stored_text_rejected` verify refusal and preservation; `test_natural_rtl_and_combining_text_allowed` and `test_unicode_round_trip` verify useful Unicode still works.

10. **Atomic replacement alone did not prevent lost updates.** Two writers could read the same counter and replace each other's additions. **Fix:** hold a persistent POSIX sidecar advisory lock across the entire load/change/save operation; reject symlink/nonregular lock objects and leave readers lock-free. **Evidence:** `test_concurrent_adds_keep_all_tasks` launches 16 additions through competing subprocesses and verifies all descriptions, IDs 1–16 and counter 17; `test_lock_symlink_rejected` verifies an unrelated target is untouched.

11. **Replacing a ledger could change its access policy.** Temporary files always used private permissions, and a writable parent could permit replacing a read-only ledger. **Fix:** preserve existing basic mode bits, retain private creation defaults and explicitly respect file writability. **Evidence:** `test_file_modes_preserved`, `test_readonly_store_cannot_be_replaced`, `test_readonly_directory_preserves_store` and `test_unreadable_store_preserved` verify actual POSIX behavior. `test_atomic_failures_preserve_original` additionally injects serialization, fsync and replacement failures, checking unchanged bytes/mtime, cleanup and no consumed ID.

12. **Stats offered counts without a progress interpretation.** Users had to calculate completion, and an empty collection lacked an explicit denominator policy. **Fix:** add a whole-percent Completion row and `n/a` for zero total; label the mixed-value column VALUE rather than COUNT. **Evidence:** `test_completion_rate` checks empty, 0%, 33% and 100%; `test_stats_counts` and `test_empty_stats` retain exact count and no-write checks. README includes the verified two-task 50% table.
