# Follow-up design-director review — twelve resolved deficiencies

Scope: every previously delivered source/document, all four test modules, the six original screenshots, both audit/result JSON files, the actual downloaded note, and both process logs were inspected. Source and prose were read; binary artifacts were checked through their headers/dimensions and the rendering code, not a claimed human visual inspection. The prior twelve-item review and 100-check result are preserved as historical records in `.verification/baseline-review.md` and `baseline-results.json`. This is a new review, not the previous list repeated.

1. **Utility typography sacrificed reading to atmosphere.** Figure captions fell to 8px at tablet size; roast metadata, recipe labels and footer information used 9–11px type. Added a 12px utility-type token across those roles, with wrapping rather than squeezing. The wordmark's small decorative subline and SVG lettering remain artwork exceptions. **Fix verified:** the browser checks all specified utility roles at 360, 768 and 1280px; all are at least 12px and none causes horizontal overflow. The new screenshots retain the cobalt/sea-glass identity without relying on tiny practical information.

2. **Three narrow tablet price cards weakened the comparison.** At 768px the subscription cards used 13px paragraphs and tight 16px padding, while annual labels competed with the price. Rebuilt 601–800px pricing as full-width editorial rows: arithmetic and identity on the left, use guidance on the right, action below. Desktop retains three columns and mobile returns to one-column cards. **Fix verified:** computed grid tracks show one outer column and two inner columns at 768px; pricing calculations still pass for all tiers and both billing periods.

3. **The mobile menu could extend beyond a short viewport.** The dropdown had no height limit or internal scrolling, making the final link vulnerable in landscape or with a reduced browser window. Added a dynamic viewport-height cap, vertical scrolling and scroll containment. **Fix verified:** real menu activation at 360 × 260 and 768 × 300 keeps the last link inside the viewport after scrolling; Escape still closes it. New `menu-360.png` and `menu-768.png` capture those states.

4. **Keyboard focus was not legible on the signature cobalt field.** A universal burnt-orange outline was used even against cobalt, while the original contrast helper checked text only. Added contextual focus tokens: pale paper on blue, cobalt on the pale featured card, plus forced-colour selected-state borders. Extended the audit to composite translucent backgrounds and sample actual focus outlines. **Fix verified:** all five billing/tier controls have solid outlines at least 3px wide and at least 3:1 against their surrounding surface at all target widths; text contrast also passes both themes. Disabled controls are correctly excluded from text-contrast requirements.

5. **Theme preference and native control appearance could disagree.** `color-scheme: light dark` did not pin browser-rendered controls to the chosen page theme; invalid stored values were accepted, and an unpinned theme ignored later system changes. Added explicit light/dark colour schemes, validated storage values, live system-following until an explicit choice, and cross-tab preference synchronisation. **Fix verified:** invalid preference → system dark, live system change → light, explicit choice remains pinned, a second real tab updates the first, and blocked storage still leaves a usable theme switch and planner.

6. **Action labels and announcements were unnecessarily difficult for assistive input.** “Add to my bag” was not a contiguous part of each card's accessible name. Adding coffee also updated two live regions, potentially announcing the same action twice. Accessible card names now begin with the exact visible action; the toast is visual-only and the persistent planner status is the single atomic live channel for plan changes. **Fix verified:** all six accessible names contain the visible label first; the toast has no live-region role, while the planner retains its live status. Capacity feedback is also written to that persistent status.

7. **The downloaded brew instructions lost their structure.** Reading the actual saved file revealed unnumbered steps because CSS counters do not survive `innerText`, with recipe values detached from their labels. Replaced export-by-rendered-text with explicit headings, `label: value` measurements and numbered steps. **Fix verified:** the real UTF-8 download contains “Coffee / water: 30 g / 480 g” and steps 1–4, with the correct bags, grind, subscription, payment and savings. The inline copy remains byte-for-text identical to the saved note.

8. **The recipe included in a saved plan was an undisclosed distant state.** A person could choose a grind in the planner but unknowingly save whichever brew tab had been visited elsewhere. Added a labelled recipe selector beside the grind, with an explicit explanation that recipe and grind are independent. It synchronises bidirectionally with the four brew tabs without moving focus or silently changing the grind. **Fix verified:** all four planner options select the corresponding panel and preserve the chosen grind; a tab change updates the selector; the export uses the visible choice.

9. **“Clear plan” destroyed a carefully built shortlist with no recovery.** Added an immediately focused “Undo clear” action with no short expiry timer. It restores bags, tier, profile, grind and billing; any subsequent plan change invalidates it so stale undo cannot overwrite new work. **Fix verified:** restoring five bags recovers ₹2,820, restoring a subscription recovers its Araku/French press/₹15,120 annual details, and a new bag selection invalidates undo. Empty-save actions remain disabled.

10. **Print styling failed the same paper-and-ink standard as the screen.** Printing from dark mode kept light text tokens on white, closed FAQ content stayed hidden, arbitrary entire-section break avoidance caused poor pagination, and native selectors did not provide a reliable record of choices. Added an A4 paper palette independent of theme, explicit printed settings, all four recipes, sensible article-level page breaks, and temporary FAQ expansion with restoration after printing. **Fix verified:** dark-mode print emulation uses white paper and dark ink, text contrast passes, all four recipes are exposed, all FAQs expand for print and their prior state is restored. Chrome produced a real `.verification/print.pdf`.

11. **The verification tooling was harder to operate and less robust than the product.** The README offered no one-command check; manual server/Chrome launch could leave processes behind, CDP requests were unbounded, the client borrowed an arbitrary tab, and the diagnostic script overwrote the historical audit. Added a standard-library `tests/run.mjs` runner with ephemeral ports, an isolated temporary profile, bounded commands, explicit error rejection, progress output and cleanup on failure. Diagnostics now write `latest-audit.json`. The oversized CSS line was also split into independently readable rules. **Fix verified:** the original behaviour suite plus new cases executes through the runner; an invalid DevTools command rejects cleanly; the runner records interruptions as failures, stops its server/browser and removes its own profile instead of silently retaining stale success. No package installation is needed.

12. **Evidence was not bound to the delivered revision.** Old passing JSON could remain after a failed run, screenshots did not include short navigation states, full-page capture was a separate manual step, and the documentation could drift from the measured counts. Added source SHA-256 fingerprints, running/passed/failed status, automatic full-page and print captures, and a read-back inventory validating every delivered artifact. Updated `DESIGN.md`, `README.md` and `QUALITY.md` to the current behaviour and test command. **Fix verified:** the inventory checks the current source hash against both browser results and run status, exact twelve-item review numbering, current prose/test counts, all JSON/UTF-8 files and all PNG/PDF headers. `QUALITY.md` records the new 132 browser checks, 1,602 visible paragraph words and explicit limits; `.verification/inventory.json` supplies per-file hashes rather than an unsupported claim of visual sign-off.
