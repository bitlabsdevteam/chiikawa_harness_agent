# Viper — follow-up design-director review

Scope: every produced source/document file, both executable suites, both text logs, results JSON and all six PNGs were inspected through source review, rendered geometry, recorded results and PNG dimensions. Baseline geometry is saved in `verification/baseline-geometry.json`. Screenshots are output evidence, not a claimed human visual audit. The previous review met numerical minima but missed these twelve concrete deficiencies. This pass replaces the previous checklist; final verification evidence will be recorded on each item after the fixes run.

1. **The mobile hero is a poster before it is a game.** At 360px the cabinet begins at y=539, the headline wraps excessively and the viper is reduced to 96px. Fix the mobile composition: a compact two-column headline/mascot pairing, full-width intro, and a larger legible mascot without absolute positioning.
2. **Start can strand the controls below the viewport.** Baseline 360px Start leaves the direction deck ending at y=1063 in an 800px window. Fit the cabinet to usable portrait heights and align the full cabinet before starting/resuming, without animated scrolling during play.
3. **Pause obscures the route and can abandon keyboard focus.** The overlay darkens the entire board while saying “Find your next turn”; focus on a direction button becomes disabled on pause or game-over without a replacement. Keep the paused board unobscured, emphasize the deck Resume action, and transfer disabled-control focus to a visible action.
4. **Reading can silently kill a round.** Leaving the cabinet for the guide keeps the snake running, although shortcuts are scoped away from the reader. Pause on guide navigation, keyboard focus leaving the cabinet and scrolling the board out of view; returning must remain explicit.
5. **The focus system and hit areas are inconsistent.** The hero link inherits an indigo focus ring on indigo and has a 21px hit area. Give every navigation action at least 44px height, make hero focus mango, and strengthen enabled tactile-control boundaries rather than relying on faint cream-on-cream outlines.
6. **Nine chapters have no usable index.** A 2,000-word guide offers no direct route to speed, pause, accessibility or saved-score advice. Add an open numbered chapter index with working anchors, focusable destinations and responsive scanning order.
7. **The pace illustration teaches the wrong curve.** Bar heights accelerate nonlinearly even though squares-per-second rises linearly; copy ambiguously says each speed increase is smaller. Correct the chart and units, and add a five-notch, text-labeled next-pace indicator so the next milestone can be planned without mental arithmetic.
8. **Another tab can erase a better record.** Best is read only at load, so a stale tab can overwrite a newer, higher score. Merge valid stored values before saving, listen for higher same-origin storage updates, and never let malformed or lower updates reduce this visit's best.
9. **The engine's invalid-input guard is incomplete.** `DIRECTIONS[next]` accepts inherited names such as `constructor` and `__proto__`; tests only try “diagonal.” Restrict turns to own direction keys, validate grid construction, and exercise a real 400-square completion as well as malformed inputs.
10. **Degraded environments offer a dead Start action.** Initial HTML enables Start with JavaScript off, and a throwing canvas context aborts initialization. Default Start to disabled, provide an immediate no-JavaScript explanation, guard context creation and provide a readable canvas-unavailable state without breaking the guide.
11. **The design system is difficult to maintain and drifts from its plan.** Nearly all CSS is one line, surface colors are repeated in rendering, radius is declared but unused, and important spacing lives in inline styles. Format the stylesheet, replace inline layout styles with named classes, use shared semantic tokens in controls and the canvas palette, and revise DESIGN.md/README.md to match actual behavior.
12. **The verification bundle can mislead its next reader.** Tests inspect document overflow but not the entire playable cabinet; screenshots have no source fingerprint; a failed rerun can leave an old passing results file; prose visibility checks differ; logs require manual redirection. Make the suites record their own logs, use deterministic browser food placement, fail closed in results JSON, check complete viewport bounds and fallback states, fingerprint source/output files, regenerate every PNG and update QUALITY.md from the measured run.
